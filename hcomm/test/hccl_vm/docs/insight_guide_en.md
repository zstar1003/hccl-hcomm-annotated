# HVRM Insight User Guide

## 1. Overview

HVRM Insight is a distributed operator visualization and analysis tool. The tool displays graph structures, memory snapshots, and validation error information from HCCL collective communication operator execution in a unified view. The tool includes three pages:

| Page | Tab | Purpose |
|------|------|------|
| **Dashboard** | Overview | Browse datasets, select ranks, and view statistics. This page is the starting point of the tool. |
| **MemView** | Correlation | Display the memory timeline and DAG task graph together. This page is the core analysis page for troubleshooting. |
| **Analytic** | Error | Display validation errors in a centralized view. Support one-click navigation to the problem context. |

---

## 2. Installation and Startup

### 2.1 Prerequisites

HVRM Insight depends on data files generated by the Checker plugin. Before use, make sure the Checker has completed execution. Enable the following two data output switches in the Checker configuration file:

The Checker configuration file is located at `/path/to/hccl_vm_install/plugin/checker/manifest.json` by default.

```json
"setting": {
    "enable_insight_dump": true,
    "enable_memory_snapshot_dump": true
}
```

- **`enable_insight_dump`**: When enabled, the Checker outputs graph structure and validation result files required by Insight during execution.
- **`enable_memory_snapshot_dump`**: When enabled, the Checker outputs memory snapshot files for each rank during execution.

Both switches default to `false`. If not enabled, the Insight tool cannot read complete analysis data.

### 2.2 Data Directory Structure

The tool reads datasets from the `data/` directory. Each dataset is a separate subdirectory:

```text
data/
└── <dataset_name>/
    ├── manifest.json        # Dataset metadata (required)
    ├── graph/               # Graph structure files (DAG)
    ├── memory/              # Memory snapshot files
    └── validation/
        └── issues.msgpack   # Validation error records (optional)
```

When an optional directory is missing, the corresponding page displays an empty state.

### 2.3 Method 1: Through hccl-vm Plugin (Recommended)

```bash
# Install and start the backend service
hccl-vm plugin install insight
# After successful installation, the terminal outputs the access URL (default `http://localhost:8000`). Open it in a browser to use the tool.

# View the access URL again
hccl-vm plugin run @insight

# Uninstall the plugin (this also stops the backend service)
hccl-vm plugin uninstall @insight
```

### 2.4 Method 2: Local Direct Startup

```bash
# Enter the insight plugin directory
python3 serve.py
```

The backend listens on `http://localhost:8000` by default. The backend provides both the frontend page and the data API.

### 2.5 Verify Successful Startup

Open the URL in a browser. If the dataset list on the Dashboard page is visible, the startup is successful. If the page is blank, check whether the `data/` directory exists and contains a `manifest.json` file.

## 4. Page Details

### 4.1 Dashboard Page

The Dashboard is the starting point of the tool. The page is divided into three areas from left to right:

- **Left side**: Operator summary and rank tree. The rank tree supports check and uncheck operations. The selection result synchronizes across all pages.
- **Center**: Dataset list. Click a row to select a dataset. The left side and right side refresh simultaneously.
- **Right side**: Detail panel for the selected dataset. The panel displays statistics and navigation buttons.

![Dashboard overview](insight_image/dashboard_overview.png)

After selecting a dataset, the right side displays detailed statistics:

![Dashboard selected dataset](insight_image/dashboard_selected.png)

The bottom of the detail panel provides two navigation entries:

- **`Enter Correlation View`**: Navigate to MemView with the current dataset and rank selection.
- **`View Diagnostics`**: Navigate to Analytic to view all validation errors for the dataset.

### 4.2 MemView Page

MemView places the memory timeline and DAG task graph in the same view for correlated display. This page is the core page for troubleshooting.

![MemView overview](insight_image/memview_overview.png)

**Page layout:**

- **Left side**: Rank selection tree, error list (Issues), and search panel.
- **Upper area**: Memory timeline — display buffer status evolution for each rank by step.
- **Lower area**: DAG task graph — display task nodes and dependency relationships by rank/stream lanes.
- **Right side**: Detail panel — display detailed information for the currently selected step or node.

![DAG node view](insight_image/memview_dag_node.png)

#### 4.3 Core Correlation Mechanism: Step, Rank, and Task Correlation

- Select a step on the timeline → the DAG highlights the corresponding node.
- Click a node in the DAG → the right side switches to node details.
- Click a navigation button on the right side → the timeline locates the corresponding step.

The **right-side detail panel** has two modes. The panel switches automatically based on whether a DAG node is selected:

- **Step detail mode**: Display the memory operation list (Task Memory Ops) and buffer slice details (Buffer Layout) for the current step. Each slice in the Buffer Layout can be expanded to view data source semantics. Click to navigate.
- **Node detail mode**: Display node attributes, parent/child node relationships, cross-stage node mappings, and memory operations associated with the node.

**Other features:**

- **Bottom player**: Support step-by-step browsing. Drag the slider for quick navigation. The playback speed is 1 second per step.
- **Focus view**: After selecting a step, the DAG automatically enters a local view. The view displays only nodes related to the current step and their context. This feature is suitable for narrowing the scope when nodes are dense.
- **Subgraph browsing**: When a node contains a subgraph, click `Open Subgraph` on the right side to view finer-grained task structures.
- **Stage switching**: Switch graph stages through the top dropdown box (such as `input_graph` / `input_task_queues`).
- **Search**: Search DAG nodes by taskId, taskType, or notifyId. Click a result to navigate to the node.

### 4.4 Analytic Page

The Analytic page displays all errors found during validation in a centralized view. The page is divided into three areas:

![Analytic error details](insight_image/analytic_issue_detail.png)

- **Left side**: Dataset and rank selection.
- **Center**: Error list. Each error displays a title, severity label (color-coded), key field summary, and original error code.
- **Right side**: Detail panel for the selected error. The panel includes basic error information, involved ranks, associated node information, slice details (for precise location of inconsistent memory positions), supplementary information, and original JSON.

The top of the detail panel provides navigation buttons:

- **`View memView`**: Navigate to MemView and locate the memory step associated with the error.
- **`View dagView`**: Navigate to MemView and locate the DAG node associated with the error directly.

The navigation automatically carries the dataset, rank, and node position information. After arriving at MemView, no re-selection is needed to start troubleshooting.

## 5. Common Usage Workflows

### 5.1 Start Analysis from the Dashboard

1. Click the target dataset in the dataset list.
2. Check the ranks to view in the left-side rank tree.
3. Confirm the file count and error statistics of the dataset on the right side.
4. Click `Enter Correlation View` to enter MemView.

### 5.2 Locate Memory Issues in MemView

1. Click the target step on the timeline (or use the bottom player to navigate).
2. View the memory operations for the step in `Task Memory Ops` on the right side.
3. Select a rank and buffer type in `Buffer Layout`. Expand a slice to view the data source.
4. Click `Locate Task` or a semantic card to navigate to the corresponding DAG node.

### 5.3 Trace Memory from a DAG Node

1. Click the target node in the DAG.
2. View `Node Memory Ops` on the right side.
3. Click `Navigate to Step` to return to the timeline, or click a parent/child node to continue tracing along the dependency chain.

### 5.4 Quick Location from Errors

1. Click an error in the Analytic page or in the MemView left-side error list.
2. View the associated nodes and slice information in the detail panel.
3. Click `View memView` or `View dagView` to navigate to the problem context.

---

## 6. Usage Tips

- Confirm the dataset and rank scope on the Dashboard first. Then enter MemView for analysis.
- When investigating memory issues, use `Task Memory Ops` and `Buffer Layout` together for troubleshooting first.
- When investigating node dependencies, select a node in the DAG first. Then use the parent/child relationships and node mappings on the right side to navigate.
- When DAG nodes are too dense, use the Focus view to narrow the scope first. Then expand gradually.
- The error list on the left side of MemView allows quick browsing and locating of error nodes without leaving the current page.

## 7. Terminology

| Term | Description |
|------|------|
| **Rank** | A single computing unit (such as an NPU). Each rank executes computations independently. |
| **DAG** | A directed acyclic graph. The graph describes dependency relationships between task nodes. |
| **Step** | A time step on the timeline. Each step corresponds to a memory state snapshot. |
| **Buffer** | A data area in memory. The buffer stores data for computation or communication. |
| **Stage** | A stage of the graph, such as `input_graph` or `input_task_queues`. |
| **Stream** | A task execution flow. Tasks within the same stream execute in order. |
| **Issue** | An error or exception record found during validation. |
